# 后端设计文档

## 1. 数据库表设计

### 1.1 任务主表 (task)

存储所有类型的任务基本信息

```sql
CREATE TABLE task (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '任务ID',
    title VARCHAR(200) NOT NULL COMMENT '任务标题',
    description TEXT COMMENT '任务描述',
    category VARCHAR(50) COMMENT '任务分类：工作/学习/健身/生活等',
    task_type TINYINT NOT NULL COMMENT '任务类型：1-年度任务 2-月度任务 3-周任务 4-临时任务 5-每日任务',
    task_status TINYINT DEFAULT 0 COMMENT '任务状态：0-待开始 1-进行中 2-已完成 3-已延迟',
    task_priority TINYINT DEFAULT 1 COMMENT '优先级：1-低 2-中 3-高',
    task_progress INT DEFAULT 0 COMMENT '进度百分比 0-100',

    -- 时间相关
    planned_start_time DATETIME COMMENT '计划开始时间',
    planned_end_time DATETIME COMMENT '计划结束时间',
    actual_start_time DATETIME COMMENT '实际开始时间',
    actual_end_time DATETIME COMMENT '实际结束时间',
    actual_duration INT COMMENT '实际用时（分钟）',

    -- 关联关系
    parent_id BIGINT COMMENT '父任务ID，用于任务层级',
    user_id BIGINT NOT NULL COMMENT '所属用户ID',

    -- 元数据
    is_deleted TINYINT DEFAULT 0 COMMENT '是否删除：0-否 1-是',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

    INDEX idx_user_type (user_id, task_type),
    INDEX idx_status (task_status),
    INDEX idx_time (planned_start_time, planned_end_time),
    INDEX idx_parent (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务主表';
```

### 1.2 子任务表 (sub\_task)

存储任务的子任务清单

```sql
CREATE TABLE sub_task (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '子任务ID',
    task_id BIGINT NOT NULL COMMENT '所属任务ID',
    title VARCHAR(200) NOT NULL COMMENT '子任务标题',
    status TINYINT DEFAULT 0 COMMENT '状态：0-未完成 1-已完成',
    sort_order INT DEFAULT 0 COMMENT '排序顺序',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    FOREIGN KEY (task_id) REFERENCES task(id) ON DELETE CASCADE,
    INDEX idx_task_id (task_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='子任务表';
```

### 1.3 用户表 (user)

存储用户基本信息

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    email VARCHAR(100) UNIQUE COMMENT '邮箱',
    phone VARCHAR(20) UNIQUE COMMENT '手机号',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    nickname VARCHAR(50) COMMENT '昵称',
    avatar_url VARCHAR(500) COMMENT '头像URL',
    status TINYINT DEFAULT 1 COMMENT '状态：0-禁用 1-启用',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_username (username),
    INDEX idx_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

### 1.4 任务状态变更表 (task\_status\_feedback)

存储任务状态变更的反馈信息，包括完成反馈、中断原因、放弃原因和延时原因

```sql
CREATE TABLE task_status_change (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '变更记录ID',
    task_id BIGINT NOT NULL COMMENT '所属任务ID',
    change_type TINYINT NOT NULL COMMENT '变更类型：1-开始 2-暂停 3-恢复 4-完成 5-放弃 6-延时',
    feedback_content TEXT COMMENT '反馈内容/原因',
    start_time DATETIME NOT NULL COMMENT '变更开始时间',
    end_time DATETIME COMMENT '变更结束时间（适用于暂停/恢复）',
    duration INT COMMENT '持续时间（分钟）',
    
    -- 关联关系
    user_id BIGINT NOT NULL COMMENT '操作用户ID',
    
    -- 元数据
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    
    FOREIGN KEY (task_id) REFERENCES task(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE,
    INDEX idx_task_type (task_id, change_type),
    INDEX idx_time (start_time, end_time),
    INDEX idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务状态变更表';
```

## 2. 核心业务逻辑

### 2.1 任务状态流转

```
待开始 -> 进行中 -> 已完成
   |         |
   v         v
已延迟 <- 暂停
```

### 2.2 关键业务规则

1. **时间冲突检测**
   - 同一用户同一时间只能有一个进行中的任务
   - 新建/调整任务时间时需要检测是否与其他任务冲突
2. **任务自动完成**
   - 当所有子任务完成时，主任务自动标记为完成
   - 实际用时根据活动日志自动计算
3. **跨日任务处理**
   - **中断跨日**：任务中断后跨日恢复时，保持原任务ID不变，通过任务时间调整记录表记录中断和恢复时间
   - **状态管理**：跨日任务的状态保持一致，直到任务完成或放弃
   - **子任务处理**：子任务状态跟随主任务，跨日时不创建新的子任务记录
   - **统计计算**：任务实际用时累计计算，跨越的天数计入总时长
4. **任务中断规则**
   - 任务中断时必须记录中断原因
   - 中断时间超过24小时的任务，系统自动标记为"已延迟"
   - 多次中断的任务，每次中断都需要记录中断原因和时间
5. **任务恢复规则**
   - 任务恢复时需要记录恢复时间和恢复原因
   - 恢复后的任务计划时间自动调整，保持原有的任务时长
   - 跨日恢复的任务，新的计划结束时间为恢复时间加上剩余任务时长

## 3. API 接口设计

### 3.1 任务管理接口

```
GET    /api/tasks                    # 获取任务列表
POST   /api/tasks                    # 创建任务
GET    /api/tasks/:id                # 获取任务详情
PUT    /api/tasks/:id                # 更新任务
DELETE /api/tasks/:id                # 删除任务

POST   /api/tasks/:id/start          # 开始任务
POST   /api/tasks/:id/pause          # 暂停任务
POST   /api/tasks/:id/complete       # 完成任务
POST   /api/tasks/:id/delay          # 延迟任务
```

### 3.2 子任务管理接口

```
GET    /api/tasks/:id/sub-tasks      # 获取子任务列表
POST   /api/tasks/:id/sub-tasks      # 添加子任务
PUT    /api/sub-tasks/:id            # 更新子任务
DELETE /api/sub-tasks/:id            # 删除子任务
POST   /api/sub-tasks/:id/toggle     # 切换完成状态
```

### 3.3 活动日志接口

```
GET    /api/tasks/:id/activities     # 获取活动日志
POST   /api/tasks/:id/activities     # 添加活动日志
```

### 3.4 统计报表接口

```
GET    /api/statistics/daily         # 每日统计
GET    /api/statistics/weekly        # 每周统计
GET    /api/statistics/monthly       # 每月统计
GET    /api/statistics/task-types    # 任务类型分布
```

### 3.5 任务状态反馈接口

```
GET    /api/tasks/:id/feedback       # 获取任务状态反馈列表
POST   /api/tasks/:id/feedback       # 提交任务状态反馈
GET    /api/feedback/:id             # 获取反馈详情
PUT    /api/feedback/:id             # 更新反馈
DELETE /api/feedback/:id             # 删除反馈
```

### 3.6 任务时间调整接口

```
GET    /api/tasks/:id/adjustments    # 获取任务时间调整记录
POST   /api/tasks/:id/adjustments    # 记录任务时间调整（中断/恢复）
GET    /api/adjustments/:id          # 获取调整记录详情
PUT    /api/adjustments/:id          # 更新调整记录
DELETE /api/adjustments/:id          # 删除调整记录
```

## 4. 数据同步策略

### 4.1 离线支持

- 本地存储待同步数据
- 网络恢复后自动同步
- 冲突解决策略：服务器优先 + 时间戳比对

### 4.2 实时更新

- WebSocket 连接用于实时通知
- 任务状态变更时推送消息
- 多端同步支持

## 5. 性能优化

### 5.1 索引优化

- 用户ID + 任务类型联合索引
- 时间范围索引用于查询
- 状态索引用于筛选

### 5.2 分页策略

- 默认每页20条
- 支持游标分页
- 大数据量时使用覆盖索引

### 5.3 缓存策略

- 用户任务列表缓存（Redis，5分钟）
- 热点数据本地缓存
- 缓存失效策略：写时失效
